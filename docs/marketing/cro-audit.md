## 0. 한눈에 보는 진단

름랩 사이트는 **카피 품질·구조·정직한 톤은 상당히 좋습니다.** 페인 → 솔루션 → 대상 → 프로세스 → 가격 → 준비물 → FAQ → CTA로 이어지는 메인 흐름은 교과서적으로 잘 짜였고, 가격을 정면 공개한 점은 큰 강점입니다.

치명적 약점은 세 가지입니다.

1. **신뢰(증거)의 전면 부재** — 후기·고객사·실적 수치·얼굴/실물 스크린샷이 0건. 포트폴리오마저 추상적 설명만 있고 클라이언트명·지표·이미지가 없습니다.
2. **전환 경로의 단절** — 멀쩡히 존재하는 상담 폼(`/consultation`)으로 가는 링크가 **메인 랜딩 어디에도 없습니다.** 메인의 모든 CTA는 `tel:`/`mailto:`뿐입니다.
3. **메시지 무게중심이 '교육'에 과하게 쏠림** — H1과 히어로 문장이 "직접 수정·운영하는 법까지 가르칩니다"에 집중되어, "**무엇을 만들어 주는 회사인지**"가 3초 안에 덜 명확합니다.

## 2. 가장 먼저 고칠 것 5개 (임팩트 × 난이도 우선순위)

> 우선순위는 **(전환 임팩트 ↑ × 구현 난이도 ↓)** 기준. 1번이 가장 먼저.

### ① 메인 랜딩에 '상담 폼'으로 가는 1차 CTA를 추가 — 전환 경로 연결
**임팩트: 높음 / 난이도: 낮음**

- **현재**: 메인의 모든 CTA(`ContactButtons`, L122-181)가 `tel:`과 `mailto:`뿐. 이미 존재하는 `/consultation` 폼으로 가는 링크는 메인 어디에도 없음(히어로의 작은 텍스트 링크는 포트폴리오로만 감, L314).
- **권장**: 히어로·가격·하단 CTA의 `ContactButtons`에 "상담 신청서 작성" 버튼(→ `/consultation/`)을 **3순위가 아니라 1차 또는 동급**으로 추가. 전화/메일은 보조로.
- **이유**: 데스크톱 사용자에게 `mailto:`는 큰 장벽(웹메일·메일앱 미설정 시 아무 일도 안 일어남). 비동기로 정보를 남길 수 있는 폼이 있는데 메인에서 도달 불가한 것은 명백한 누수. analytics 태그(`data-analytics`)도 이미 깔려 있어 측정만 붙이면 됨.

### ② 상담 폼을 mailto에서 실제 서버 전송으로 전환 — 제출 성공률 확보
**임팩트: 높음 / 난이도: 중간**

- **현재**: 제출 시 `window.location.href = buildMailtoConsultation(fd)`로 사용자 메일 앱을 염(Form L39). 버튼 라벨 "보내기 (메일 앱)", 성공 화면도 "직접 보내기를 눌러 주세요"(L50-53)로 **마지막 전송 책임을 사용자에게 전가**. 정적 export라 자체 백엔드는 없음.
- **권장**: 정적 호스팅에서도 동작하는 폼 백엔드(Netlify Forms / Formspree / 외부 폼 엔드포인트 등)로 전환해 **버튼 한 번에 실제 접수 완료**되게. 성공 화면은 "접수 완료, 영업일 기준 N시간 내 회신" 같은 명확한 기대치로 교체. (참고: 이미 다른 작업에서 mailto→실폼 전환이 진행 중이라면, 이 항목과 동일 방향이며 본 감사는 그 개선을 강력히 지지함.)
- **이유**: mailto는 모바일/웹메일 환경에서 실패·이탈률이 구조적으로 높음(추측이지만 업계 공통 현상). 폼은 전환의 마지막 1m인데 여기서 새는 것이 가장 아까움.

### ③ 사회적 증거(후기·실적·고객사) 섹션을 메인과 포트폴리오에 신설 — 신뢰 0점 해소
**임팩트: 높음 / 난이도: 중간** (콘텐츠 수급이 변수)

- **현재**: 후기·고객사·정량 실적·실물 스크린샷이 전 페이지에 0건. 포트폴리오 사례도 익명 일반명사(`portfolio-cases.ts`)뿐이고 지표·이미지 없음.
- **권장**: (a) 메인 '름랩이 다른 점'(L382~) 직후에 **후기 1~3건 + 간단한 실적 요약** 섹션 추가. (b) 포트폴리오 카드/상세에 가능한 범위에서 **결과 지표(예: 출시 기간, 처리 데이터 규모 등)와 스크린샷/목업 이미지** 추가. 실명·로고 사용이 어려우면 "OO업종 대표님" + 동의받은 한 줄 후기라도.
- **이유**: 가격·차별점은 강한데 "**그래서 실제로 잘했어?**"에 답하는 증거가 전무. 1인 스튜디오일수록 신뢰 갭이 크므로, 후기 한 줄이 가격 공개만큼의 전환 레버가 됨. 없는 실적을 지어내지 말고 보유한 사실만 사용할 것.

### ④ 히어로 메시지에 '무엇을 만드는가'를 한 줄로 선명하게 — '교육' 편중 완화
**임팩트: 중간~높음 / 난이도: 낮음**

- **현재**: H1 "앱·웹은 만드는 것보다 끌려다니지 않고 굴리는 것이 더 어렵습니다"(L300) + 서브 강조가 "직접 수정·운영하는 법까지 1:1로 가르칩니다"(L307). '교육' 메시지가 전면에 서서, 첫인상이 '개발사'보다 '교육 서비스'로 읽힐 여지.
- **권장**: H1 위 또는 H1 자체에 **"VAT 포함 정액 · 앱/웹 개발 스튜디오"** 같은 기능적 정체성을 명시. 교육·운영 자립은 차별점(서브카피/배지)으로 한 단계 내려 배치. 톤(솔직·담백)은 유지.
- **이유**: 3초 룰 — 방문자는 먼저 "여기가 내가 찾던 개발사인가?"를 판단하고, 그다음에 차별점에 설득됨. 정체성→차별점 순서를 명확히 하면 이탈 전 이해도가 올라감. 카피 교체만으로 가능해 난이도 낮음.

### ⑤ 폰트 로딩 최적화 (next/font + 패밀리 축소) — LCP/CLS 개선
**임팩트: 중간 / 난이도: 낮음~중간**

- **현재**: `app/layout.tsx`(L62-64)에서 Google Fonts를 **4개 패밀리(Plus Jakarta Sans, Noto Sans KR, JetBrains Mono, Outfit), 다수 weight**로 렌더 블로킹 `<link rel="stylesheet">` 로드. `next/font` 미사용. preconnect는 되어 있음.
- **권장**: `next/font/google`로 전환해 self-host + 자동 `font-display: swap` + 서브셋 적용, 실제 안 쓰는 패밀리/weight 제거(특히 한글은 Noto Sans KR weight 수가 용량의 대부분). 또는 한글 본문 폰트의 서브셋(`&subset=korean`)·필요 weight만 남기기.
- **이유**: 한글 웹폰트는 용량이 커 모바일 첫 로딩 LCP에 직접 영향. 정적 export로 인프라는 이미 빠른데, 폰트가 병목일 가능성이 높음(추측: 실측 LCP 데이터는 코드만으로 확인 불가). next/font는 빌드 타임 처리라 정적 export와도 호환.

## 3. 보너스 — 빠른 추가 개선 (Quick wins)

- **포트폴리오 카드에 전환 CTA 부재**: 카드는 '상세 보기 →'만 있음(page L76-78). 섹션 끝마다 '이런 거 만들고 싶으세요? 상담' 같은 폼 연결 CTA 추가 권장.
- **상담 폼 문의 유형 옵션 누락**: `select`에 '앱 개발/웹 개발'만 있음(Form L78-82). 가격표의 '고도화'·'잘 모르겠음' 옵션 추가 시 리드 분류·전환 모두 개선.
- **메인↔포트폴리오 상호 연결 약함**: 메인에서 포트폴리오로 가는 건 히어로 작은 텍스트 링크 1곳(L314)뿐. 솔루션/프로세스 섹션 근처에 '실제 사례 보기' 버튼 추가 권장.
- **개인정보 수집 동의 안내 부재(추측)**: 상담 폼에 개인정보 처리방침/동의 문구가 코드상 보이지 않음 — 법적 리스크 겸 신뢰 요소이므로 점검 필요.
- **`<img>`/스크린샷 0건**: 신뢰·이해도 측면에선 단점이나, 추가 시 ②/⑤의 로딩 최적화(`images:unoptimized` 상태)와 함께 이미지 압축·사이즈 지정으로 CLS 관리 필요.

## 4. 측정 권고 (실행 후 검증용)

코드에 `data-analytics`(예: `cta_call`, `cta_mail`, `cta_pkg_call`, `cta_hero_portfolio`)와 `AnalyticsDataLayer`가 이미 존재합니다. 위 ①~⑤ 적용 후 다음을 비교하세요.

- 히어로 노출 → 폼 도달률, 폼 도달 → 제출 완료율(②의 핵심 지표)
- 전화/메일 CTA vs 폼 CTA 클릭 비중(①의 효과)
- 후기 섹션 도입 전후 가격 섹션 → CTA 전환율(③의 효과)

> 본 리포트의 모든 정량 표현은 소스코드에서 확인 가능한 사실에 한정했으며, 트래픽·전환율 등 실측 데이터는 코드만으로 알 수 없어 포함하지 않았습니다.
