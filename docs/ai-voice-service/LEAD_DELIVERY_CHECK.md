# LEAD_DELIVERY_CHECK — 문의 접수 경로 검증

> **결론: `LEAD_DELIVERY_VERIFIED = false (BLOCKED)`**
> 클라이언트 쪽 동작은 전부 확인했지만, **실제 접수 저장과 담당자 알림은 이 환경에서
> 확인할 수 없었다.** 공개 전에 운영자가 §4 절차로 직접 확인해야 한다.

---

## 1. 접수 경로 (확인된 구조)

```
방문자 입력
  ↓  components/LandingInquiryForm.tsx (variant="ai-voice")
  ↓  fetch('/__forms.html', POST, application/x-www-form-urlencoded)
  ↓  Netlify Forms 가 `main-apply` 폼으로 인식해 접수 저장     ← ★ 미검증
  ↓  [Netlify 알림 설정 → 담당자 수신]                          ← ★ 미검증
```

- 폼 이름 `main-apply` — 홈·GEO·AI 검색 페이지와 **같은 접수함**을 쓴다
- 허니팟 `bot-field` · hidden `form-name` 유지
- 감지 스켈레톤 원본: `public/__forms.html` (빌드가 `out/__forms.html` 로 복사)
- 서버 API 를 새로 만들지 않았다 — 정적 export 에서는 실행되지 않기 때문이다

## 2. 이번에 추가된 필드

| 화면 라벨 | 저장 필드명 | 값 |
|---|---|---|
| 업종 | `음성_업종` | 미정 / 학원 / 병원·의원 / 미용실·뷰티 / 부동산 / B2B·전문서비스 / 고객센터 / 기타 |
| 하루 전화량 | `음성_하루전화량` | 미정 / 10건 미만 / 10~30건 / 31~100건 / 101건 이상 |
| 관심 구축 범위 | `음성_관심상품` | 미정 / Starter / Business / Enterprise |

세 필드 모두 기본값 **"미정"** 이다. 아무것도 누르지 않은 방문자가 특정 업종·상품을
신청한 상태가 되지 않는다.

기존 필드 `현재응대방식`(기본값을 "선택 안 함"으로 변경) · `연동대상시스템`(200자 상한 추가) ·
`핵심기능`(1,000자 상한 + 민감정보 안내) 는 이름을 바꾸지 않았다.

**필드 이름 단일 출처**: `lib/ai-voice-form.ts` 의 `VOICE_FIELD_NAMES`.
여기를 고치면 `public/__forms.html` 도 함께 고쳐야 하며, 검사기가 불일치를 빌드에서 막는다.

## 3. 이 환경에서 확인한 것 (브라우저 실측)

Chromium 에서 네트워크를 가로채(route) 응답을 흉내 낸 검수다.
**실제 접수 시스템으로 아무것도 보내지 않았다** — 담당자에게 테스트 알림이 가지 않는다.

| 항목 | 결과 |
|---|---|
| 정상 응답 시 POST 횟수 | **1회** · 성공 화면 표시 |
| 성공 문구 | "도입 검토 요청이 접수되었습니다. 담당자가 내용을 확인한 뒤…" (회신 시간·견적을 약속하지 않음) |
| 전환 이벤트 | `generate_lead` 1 · `inquiry_form_submit` 1 · `main_apply_submit` 1 · `form_submit_success` 1 — **1건당 정확히 1회** |
| 느린 응답 중 6회 연타 | POST **1회** · 전환 **1회** (중복 없음) |
| HTTP 500 | 허위 성공 **없음** · 전환 **0회** · 입력 전부 보존 · 전화 대안 노출 · `error_type=server` |
| 네트워크 실패 | 위와 동일 · `error_type=network` |
| 타임아웃(20초) | "응답이 오지 않아 접수 여부를 확인하지 못했습니다" — **접수 실패라고 단정하지 않고** 중복 접수 주의를 안내 |
| 필수 미입력 | POST **0회** · 브라우저 검증이 막음 |
| 대표번호(02-…) | 허용됨 — 010 으로 제한하지 않음 |
| 길이 상한 | 업무 설명 1,000자 · 연동 시스템 200자에서 잘림 |
| dataLayer PII | 이름·연락처·문의 원문 **0건** |
| 감지 스켈레톤 동기화 | 폼 30필드 전부 `out/__forms.html` 에 등록됨 |

### 3.1 JS 를 끈 상태의 기본 제출 (실측)

자바스크립트를 끈 Chromium 에서 입력 후 제출 버튼을 누르고, 나가는 요청을 가로채 확인했다.

```
POST http://…/ai-voice-development/
Content-Type: application/x-www-form-urlencoded
form-name       = main-apply
필드 수          = 30개
이름            = [테스트] 비JS 제출
휴대폰번호       = 010-0000-0000
개인정보동의     = 동의
음성_업종        = 학원
음성_하루전화량   = 10~30건
음성_관심상품     = Business
문의서비스       = AI 전화상담 직원 구축
유입_랜딩        = /ai-voice-development/
bot-field       = (빈 값 — 정상)
```

- 필수값을 비우고 제출하면 **브라우저가 막는다(POST 0회)**
- `/geo-website/` 도 같은 방식으로 27필드가 정상 전송됨(기존 폼 회귀 없음)
- `action` 속성이 없어 **현재 주소로 POST** 되고, Netlify Forms 가 `form-name` 으로 가로챈다
  — 홈(`index.html`)의 `main-apply` 폼이 쓰는 것과 **같은 경로**다
- 성공 후 화면은 Netlify 기본 완료 페이지다(홈 폼과 동일한 동작)

즉 **브라우저 쪽은 정상이고, 남은 미검증 구간은 Netlify 가 그 POST 를 받아 저장하는 부분**뿐이다.

## 4. 확인하지 못한 것과 그 이유

| 항목 | 상태 | 이유 |
|---|---|---|
| Netlify Forms 실제 저장 | **BLOCKED** | 이 컨테이너의 프록시가 `reumlab.com` · `*.netlify.app` 으로의 CONNECT 를 403 으로 차단한다. 실제 POST 자체가 불가능하다 |
| 담당자 알림 수신 | **BLOCKED** | Netlify 대시보드의 알림 설정 영역. 저장소에서 확인할 수 없다 |
| 신규 필드 3종이 접수 화면에 실제로 표시되는지 | **BLOCKED** | 위와 같음. 감지 스켈레톤에 등록된 것까지만 확인했다 |
| JS 없이 native 제출이 Netlify 에 **접수되는지** | **BLOCKED** | 같은 이유(프록시 차단). 다만 **브라우저가 올바른 POST 를 내보내는 것까지는 확인했다** — 아래 §3.1 |

**로컬 정적 서버가 POST 에 200 을 돌려주는 것을 접수 성공으로 인정하지 않았다.**
클라이언트 네트워크 성공과 운영상 저장·알림 성공은 다른 일이다.
JS 없이 나가는 POST 도 마찬가지로 "브라우저가 올바르게 보냈다"까지만 확인된 것이다.

## 5. 운영자가 공개 전에 해야 할 확인 (순서대로)

1. **배포 미리보기 또는 운영 배포**를 만든다.
2. 해당 URL 의 `/ai-voice-development/` 에서 폼을 **1건만** 제출한다.
   - 이름에 `[테스트]` 를 넣어 실제 문의와 구분한다.
   - 업종·하루 전화량·관심 구축 범위를 **각각 기본값이 아닌 값**으로 골라 저장 여부를 본다.
   - 중복·대량 제출을 하지 않는다.
3. Netlify 대시보드 → **Forms → main-apply** 에서 해당 건이 보이는지 확인한다.
4. 접수 상세에 아래 3개 필드가 **값과 함께** 있는지 확인한다.
   `음성_업종` · `음성_하루전화량` · `음성_관심상품`
   - 값이 비어 있거나 필드 자체가 없다면 → Netlify 의 폼 스키마가 갱신되지 않은 것이다.
     새 배포를 한 번 더 해서 `__forms.html` 을 다시 감지시킨다.
5. 설정한 알림 채널(이메일 등)로 **실제로 도착했는지** 확인한다.
6. 저장은 됐는데 알림만 실패한 경우 → **새 문의를 반복 생성하지 말고** 운영 이슈로 기록한다.
7. 확인이 끝나면 테스트 접수 1건을 삭제하거나 테스트로 표시한다.

이 5~6번이 확인되기 전까지 이 페이지를 **"도입 문의 접수까지 운영 검증된 페이지"** 라고
설명하지 않는다. 검증된 전화·이메일 경로는 이미 화면에 있으므로, 폼 수신이 미검증인 상태로도
공개 자체는 가능하다 — 다만 그 구분을 보고서와 운영 안내에 유지한다.

## 6. 개인정보 관련 확인 사항

- 이 페이지의 시뮬레이션은 **실제 통화나 마이크 입력을 수집하지 않는다.**
- 문의 폼의 자유 입력에는 "실제 고객 이름·연락처·상담 원문처럼 민감한 정보는 적지 말아 달라"는
  안내를 화면에 표시했다.
- 상담 원문·이메일·전화번호·연동 시스템 자유 입력은 dataLayer·콘솔·브라우저 저장소에
  넣지 않는다(브라우저 실측으로 확인).
- 개인정보 동의는 **사전 체크되지 않는다.** 광고·마케팅 동의와 묶지 않았다.
- `/privacy/` 링크가 실재함을 검사기가 확인한다.
- 이번에 추가한 3개 필드는 전부 **선택지(enum)** 이며 개인 식별 정보가 아니다.
  따라서 처리방침의 수집 항목 문구 변경이 필요한지는 운영자 판단 사항으로 남긴다
  (§OWNER_ACTIONS).
- **HTML 체크박스만으로 적법성이 완성되지 않는다.** 실제 수집·전송·보관 구성에 대한
  검토는 별도 사안이며, 이 구현 검수로 인증되지 않는다.
