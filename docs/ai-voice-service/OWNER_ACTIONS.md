## 🔴 1. 문의 폼 실제 수신 확인 — 가장 중요

**왜 제가 못 했나**: 이 작업 환경의 프록시가 `reumlab.com` 과 `*.netlify.app` 으로의
연결을 차단합니다(403). 실제 POST 를 보낼 수 없어 **접수 저장과 담당자 알림을
확인하지 못했습니다.** 로컬에서 200 이 나오는 것을 접수 성공으로 치지 않았습니다.

**해야 할 일** (자세한 절차는 `LEAD_DELIVERY_CHECK.md` §5)

1. 미리보기 또는 운영 배포에서 `/ai-voice-development/` 폼을 **1건만** 제출
   - 이름에 `[테스트]` 표기
   - 업종 · 하루 전화량 · 관심 구축 범위를 **각각 기본값이 아닌 값**으로 선택
2. Netlify → Forms → `main-apply` 에 그 건이 보이는지 확인
3. 접수 상세에 아래 3개 필드가 **값과 함께** 있는지 확인
   `음성_업종` · `음성_하루전화량` · `음성_관심상품`
4. 알림 채널로 실제 도착했는지 확인
5. 확인 후 테스트 접수를 삭제하거나 테스트로 표시

**필드가 비어 있으면**: 배포를 한 번 더 해서 Netlify 가 `__forms.html` 을 다시 감지하게 합니다.
**저장은 되는데 알림만 안 오면**: 새 문의를 반복 생성하지 말고 알림 설정을 점검하세요.

## 🟡 2. 개인정보 처리방침 반영 여부 판단

이번에 추가한 3개 필드(`음성_업종`, `음성_하루전화량`, `음성_관심상품`)는
**전부 선택지(enum)이고 개인 식별 정보가 아닙니다.** 이름·연락처 같은 수집 항목은
늘어나지 않았습니다.

그래도 처리방침의 "수집 항목" 문구에 이 3개를 명시할지는 **운영자 판단 사항**입니다.
수집 근거·항목·목적·보관기간·동의 방식은 개발자가 임의로 정할 수 없는 정책이라
이번에 처리방침을 고치지 않았습니다.

- 명시하기로 하면: `public/privacy/index.html` 과 `privacy.html` 을 함께 수정
- 그대로 두기로 하면: 별도 조치 없음

또한 **실제 운영 환경의 적법성 검토**(어디에 저장되는지, 외부 서비스로 무엇이 전달되는지,
접근 권한은 누가 갖는지)는 이 페이지 구현 검수로 인증되지 않습니다. 별도 확인이 필요합니다.

## 🟡 3. 운영 도메인에서 성능·화면 재확인

로컬 측정에서 모바일 Performance 가 **68**로 목표(90)에 미달했습니다.
다만 같은 환경에서 **손대지 않은 페이지도 68**, 기준선 이 페이지도 **69** 였습니다
(자세한 근거는 `QA_REPORT.md` §2). 즉 이번 변경 때문에 생긴 회귀가 아니라
로컬 측정 환경·기존 사이트의 공통 조건입니다.

운영 도메인은 CDN·압축·HTTP/2 가 붙어 수치가 다릅니다. 배포 후 한 번 측정해 두시면
이후 비교 기준이 생깁니다. **실사용자 INP 는 현장 데이터 없이는 알 수 없습니다.**

## 🟢 4. 검색엔진 등록 (기존 절차대로)

이 페이지는 **신규 URL 이 아니라 기존 경로의 갱신**입니다.
사이트맵 URL 수는 780개 그대로이고, canonical 도 바뀌지 않았습니다.

- Google Search Console — 색인 재요청(선택)
- 네이버 서치어드바이저 — 수집 요청(선택)
- IndexNow — production 배포 시 기존 흐름이 자동 처리합니다. **따로 실행하지 마세요.**

IndexNow 가 200 을 돌려줘도 그것은 "접수됨"이지 "색인 완료"가 아닙니다.
검색 순위·AI 추천·트래픽 증가는 보장되지 않습니다.
