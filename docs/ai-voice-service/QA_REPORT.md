## 2. Performance 68 — 신규 회귀가 아니라는 근거

명세 §13.4 의 실험실 목표는 모바일 Performance ≥90 이다. **미달했다.**
다만 이것이 이번 변경 때문인지 분리하기 위해 같은 환경·같은 방법으로 3개를 측정했다.

| 측정 대상 | Performance | LCP | CLS |
|---|---:|---:|---:|
| 기준선 `a5aa77e` 의 `/ai-voice-development/` | **69** | 6.46s | 0.0009 |
| 현재 `/ai-voice-development/` | **68** | 6.90s | 0.0009 |
| 이번에 손대지 않은 `/ai-search-optimization/` | **68** | 6.61s | 0.0007 |

측정 조건: Lighthouse 13.4.1 · 모바일 에뮬레이션(412×823, DPR 1.75) · 로컬 정적 서버 · **3회, 중앙값**
개별값 perf `69/68/67`.

**해석**: 세 페이지가 모두 68~69 이고 LCP 가 모두 6.5초 내외다.
이 수치는 로컬 `http-server` + Lighthouse 의 시뮬레이션 스로틀링(느린 4G·CPU 4배 감속)
조건에서 나온 값이며, 손대지 않은 페이지도 동일하다.
→ **이번 변경으로 생긴 회귀가 아니라 이 측정 환경·기존 사이트의 공통 조건**이다.
→ 다만 목표 미달 사실 자체는 그대로 보고한다. 실제 운영 도메인(CDN·압축·HTTP/2)의
  수치는 배포 후 별도 측정이 필요하며, 이 보고서로 대신하지 않는다.

`INP` 는 **FIELD_DATA_NOT_AVAILABLE** — 현장 데이터가 없으므로 Lighthouse 점수로
실사용 INP 를 PASS 처리하지 않는다. TBT 는 31ms 로 측정됐다.
