# 8. 디자인 리뷰 (실제 캡처 기준)

코드가 아니라 렌더링 캡처를 보고 검토했습니다. 스스로 붙인 점수는 쓰지 않습니다.
캡처: `shots/` (1280 / 390 전체·첫 화면, 주요 섹션 Before/After)

기록 형식: **위치 / 관찰된 현상 / 수정 이유 / 수정 값 또는 방법 / 재확인 결과**

### R-1 · Hero 설명문에서 조사가 명사와 떨어져 보임

- **위치**: `.hero__note` (`shots/sec-hero-before.jpg`, `shots/390-fold-before.jpg`)
- **관찰**: `름랩(REUMLAB)` 과 `은` 사이가 10px 벌어짐. 390px 에서는 두 조각이 다른 줄로 갈라짐.
  두 번째 설명문도 `…예상 범위` / `를 안내드립니다.` 로 끊김.
- **이유**: `display:flex; gap:10px` 이라 `<b>` 와 뒤 텍스트 노드가 각각 flex 항목이 됨.
  한국어 문장이 문장으로 읽히지 않음.
- **수정**: 홈 스코프에서 `display: block; line-height: 1.7; max-width: 36em`, `text-wrap: pretty`.
- **재확인**: 6뷰포트 전부에서 한 문장으로 이어짐. 렌더 텍스트가 **HTML 원문과 일치**하게 됨
  (변경 전에는 원문에 없는 공백이 들어가 있었음). 공백 제외 글자 수 8,198자로 전후 동일.

### R-2 · 한국어 단어가 음절 단위로 잘림

- **위치**: `.hero__trust li`(390px `단일 창`/`구`), `.purpose-card__desc`(`관리`/`자 시스템`),
  가격 `.sec-sub`(`고르`/`세요`), `.price-incl li`(`1세`/`트`, `교`/`육`, `가이`/`드` 등 다수)
- **관찰**: 좁은 칼럼에서 어절 중간이 끊김. 가격 카드는 4열이라 특히 잦음.
- **이유**: 지시서 6-C — 한국어 음절이 잘리거나 단어가 어색하게 고립되면 안 됨.
- **수정**: 홈 제목·본문·목록·버튼·표에 `word-break: keep-all` + `overflow-wrap: break-word`.
  (`keep-all` 만 쓰면 좁은 칼럼에서 넘치므로, 한 줄에 못 들어갈 때만 끊기게 둠)
  모바일 신뢰 칩은 2열 그리드를 풀어 자연스럽게 흐르도록 변경.
- **재확인**: `shots/sec-pricing-after.jpg`, `shots/sec-purpose-after.jpg`, `shots/390-fold-after.jpg`
  에서 위 사례 전부 어절 경계로 끊김. 320px·200% 확대에서도 가로 넘침 0.

### R-3 · 가격 8칸의 기준선이 어긋나 비교가 어려움

- **위치**: `#pricing` 의 `.price-card.featured` 2장
- **관찰**: 추천 카드만 1.025배로 커져 금액·기간·포함 항목 줄이 좌우 카드와 어긋남.
  금액 자릿수도 카드마다 폭이 달라 세로로 정렬되지 않음.
- **이유**: 지시서 7-가격 "모바일에서 각 가격이 어느 상품의 어떤 조건인지 분명하게 읽히게".
  Apple Mac 의 "선택지를 비교하기 쉬운 정렬".
- **수정**: `transform: none`(featured 확대 제거, hover 이동도 제거),
  `.price-amount { font-variant-numeric: tabular-nums; font-size: 32px }`.
  강조는 크기 대신 기존 네이비 배경·라임 배지로만.
- **재확인**: 8칸 금액이 같은 높이에 정렬됨. 금액·VAT·기간·포함/제외 문구는 전부 그대로
  (보호 manifest `prices` PASS).

### R-4 · 첫 화면을 장식이 차지함

- **위치**: `.hero::before` (radial-gradient 2겹), `.hero` linear-gradient 배경
- **관찰**: 1280px 에서 제목 위아래로 빈 캔버스가 넓고, 배경 그라데이션이 목업과 겹쳐 뿌옇게 보임.
- **이유**: 지시서 6-B "1차안은 장식용 그라데이션·글래스·네온·과한 그림자를 사용하지 않는다",
  7-Hero "첫 화면을 빈 공간이나 장식이 독점하지 않게 한다".
- **수정**: `.hero::before { content: none }`, 배경 `var(--white)`,
  상하 여백 86/104 → 80/96(모바일 48/64), 목업 `drop-shadow` 제거.
- **재확인**: `shots/1280-fold-after.jpg` — 첫 화면에 제목·설명·정의문·신뢰 칩·CTA 2개가 모두 들어옴.
  390px 에서도 CTA 2개까지 첫 화면 안. 데스크톱 LCP 456→392ms.

### R-5 · 카드 그림자가 무거워 면이 뭉개짐

- **위치**: `.card` `.stype__card` `.flow__step` `.price-card` `.purpose-card` `.hlist li` `.edu-card`
- **관찰**: `--shadow`/`--shadow-lg` 가 넓게 쓰여 카드끼리 경계가 흐릿하고 배경이 탁해 보임.
- **이유**: 지시서 6-D "카드보다 제목·정렬·배경·구분 간격으로 영역을 나누는 방법을 먼저 검토".
- **수정**: 홈 스코프에서 `--h-elev-1`(1px+2px) + `--h-line` 머리카락 경계선으로 교체.
  radius 는 12/20/28px 3단계로 정리.
- **재확인**: `shots/sec-purpose-after.jpg`, `shots/sec-pricing-after.jpg` — 카드가 면으로 구분되고
  배경 톤(`#f6f8fc`)이 살아남. 콘텐츠 변화 없음.

### R-6 · 조작 요소의 포커스·상태 규칙이 제각각

- **위치**: 홈 전체 (링크·버튼·입력·필터 칩)
- **관찰**: `focus-visible` 규칙이 저장소 전체에 1개(`.pf-filter__btn`)뿐. 버튼 hover 는
  요소마다 `translateY(-2px)`/`-4px`/`-5px` 로 다름. 필터 칩은 42px.
- **이유**: 지시서 6-E "hover, active, focus-visible, disabled 상태를 일관되게 정리한다",
  "주요 버튼은 약 44px 이상의 조작 영역".
- **수정**: 홈 스코프에서 `a/button/input/select/textarea/[tabindex]` 에 같은 포커스 링
  (`3px rgba(40,94,219,.55)`, offset 2px). 버튼 hover 는 이동 대신 배경색 변화만(140ms).
  `.pf-filter__btn` 44px, `.faq-q` 64px.
- **재확인**: Tab 14회 전부 보이는 포커스 링(데스크톱·모바일 모두 PASS).
  44px 미만으로 줄어든 요소 0개, 44px 이상으로 커진 요소 뷰포트당 6~8개.

### R-7 · `#contact` 왼쪽 안내 옆이 크게 빔

- **위치**: `.final__intro` (1280px)
- **관찰**: 왼쪽 안내가 짧고 오른쪽 폼이 길어, 스크롤하면 왼쪽이 먼저 사라지고 큰 여백만 남음.
- **이유**: 지시서 12 "장식보다 서비스와 공개 결과물이 중심인가".
- **수정**: `@media (min-width: 901px)` 에서 `position: sticky; top: 108px; align-self: start`.
  grid 열 안에서만 붙으므로 본문을 가리지 않음. 제목 `clamp(26px, 2.9vw, 38px)`,
  연락 링크 `white-space: nowrap`(`카카오톡 채널` 이 `카카오톡`/`채널` 로 갈리던 문제).
- **재확인**: `shots/sec-contact-after.jpg` — 제목이 두 줄로 균형 잡히고 연락 링크가 붙어 있음.
  고정 요소가 본문을 가리는 사례 없음(가로 넘침 0, 문서 가로 스크롤 없음).

## 섹션별 점검 (지시서 12절 질문)

| 질문 | 결과 |
|---|---|
| 먼저 보일 것이 분명한가 | Hero·각 섹션에서 eyebrow → 제목 → 설명 → CTA 순으로 크기·굵기·간격이 단조 증가·감소 |
| 기존 문구 그대로 읽기 쉬워졌는가 | 문구 1글자도 바꾸지 않고 줄바꿈·행간·폭만 조정 (보호 manifest 전항목 PASS) |
| 이미지와 설명이 같은 이야기를 하는가 | 이미지·alt·caption 전부 그대로. 목업 고지문도 그대로 |
| 폰트·간격·정렬·버튼 상태가 같은 규칙인가 | 홈 전용 토큰 1벌(간격 11단계·radius 3단계·모션 2단계)로 통일 |
| 모바일이 PC 축소판이 아닌가 | 신뢰 칩 흐름 배치, 섹션 여백 96→64, 제목 28px, FAQ 패딩 축소 등 별도 규칙 |
| 원래 볼 수 있던 내용·조건·링크를 여전히 찾을 수 있는가 | 화면 텍스트 8,198자·링크 115개·가격 8종 전부 동일, 새 접힘 구조 0개 |
| 장식보다 서비스·공개 결과물이 중심인가 | 장식 그라데이션 제거, 그림자 축소, 목업·가격·사례가 화면을 차지 |

## 이번 범위에서 해결하지 못한 것

- **Hero 오른쪽 목업 열의 상하 여백**: 1280px 에서 왼쪽 텍스트가 길고 목업이 세로로 짧아
  아래가 빕니다. 목업 자체의 크기·구성을 바꾸면 기존 공개 자산의 표현이 달라지므로
  이번 1차안에서는 배치만 정리하고 남겨 둡니다. **콘텐츠를 지워서 해결하지 않았습니다.**
- **`.section--tight` 네이비 지표 밴드와 위아래 섹션의 색 대비**: 강한 면 전환이라
  Apple 계열의 부드러운 리듬과는 다릅니다. 배경색을 바꾸면 지표 밴드의 흰 글자 대비가
  달라지므로 이번에는 유지했습니다.
- `06-baseline-issues.md` 의 B-1·B-2 는 범위 밖이라 손대지 않았습니다.
