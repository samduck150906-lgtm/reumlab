# 6. 변경 전부터 있던 문제 (BASELINE ISSUE)

지시서 0절·4절에 따라 **이번 작업에서 고치지 않았습니다.**
"작업 범위 밖의 버그를 겸사겸사 수정" 하지 않고, 승인 필요 항목으로 분리합니다.
변경 후에도 값이 그대로인지 확인해 **제가 몰래 바꾸지 않았다는 것**까지 검사에 넣었습니다.

## B-1. 홈과 목적별 랜딩 9개 페이지에서 JS 런타임 오류 — 매 로드

```
Uncaught ReferenceError: updateMobileCta is not defined
```

- **위치**: `script.js:693` (호출) / `script.js:679` (선언)
- **원인**: 파일 전체가 `"use strict"` 이고, `updateMobileCta` 가 `if (mcta) { … }` **블록 안**에
  선언되어 있습니다. strict 모드에서 블록 안 함수 선언은 그 블록에만 묶입니다.
  바로 다음 `if (mcta && contact && …)` 블록의 IntersectionObserver 콜백이 그 이름을 찾지 못합니다.
- **증상**: `#contact` 가 화면에 들어오고 나갈 때 모바일 고정 CTA 바의 표시/숨김 갱신이
  그 시점부터 동작하지 않고, 콘솔에 오류가 남습니다.
- **영향 범위**: 홈 `/` 과 `script.js` 를 공유하는 목적별 랜딩 8개.
- **확인**: 변경 전/후 6개 뷰포트 전부에서 동일하게 1건 발생 (`evidence/diff-render.json`).
- **제안 패치(미적용, 1줄 이동)**: `var contactVisible` 과 `function updateMobileCta` 를
  `if (mcta) {` 블록 **밖**(같은 IIFE 스코프)으로 올립니다.
- **왜 지금 안 고쳤나**: `script.js` 는 이번 범위(홈 시각 레이어) 밖이고,
  홈과 랜딩 8개가 공유하는 파일이라 별도 검증이 필요합니다.

## B-2. 모바일 메뉴 안 "프로젝트 상담하기" 버튼 대비 3.05:1 (기준 4.5:1)

- **위치**: 모바일 메뉴(`#mobileNav`)의 `.btn.btn--primary`
- **측정값**: 글자 `rgb(11,27,51)` / 배경 `rgb(40,94,219)` → **3.05:1**, 17px/600 이므로 기준 4.5:1
- **원인**: `styles.css:204` `.mobile-nav a { … color: var(--ink); }` 의 특이도(0,1,1)가
  `styles.css:133` `.btn--primary { color: #fff }` (0,1,0) 보다 높아 흰 글자를 덮습니다.
- **나타나는 폭**: 360 / 390 / 430 / 768px (모바일 메뉴가 보이는 구간)
- **변경 후에도 3.05:1 그대로** — 이번 변경이 만든 것도, 고친 것도 아닙니다.
- **제안 패치(미적용, 1줄)**: `.mobile-nav a.btn--primary { color: #fff; }`
- **왜 지금 안 고쳤나**: 접근성 결함이지만 이번 지시서가 기존 결함의 임의 수정을 금지하고
  승인 항목으로 분리하라고 정하기 때문입니다. **승인해 주시면 1줄로 반영 가능합니다.**

## B-4. Hero 폰트 로딩 시 레이아웃 이동 (CLS)

- 데스크톱 1280px 에서 약 500~650ms 에 레이아웃 이동 1건이 항상 발생합니다.
  Pretendard 로딩 후 Hero 텍스트 높이가 바뀌며 `.hero__trust` · `.hero__cta` · 목업 열이 밀립니다.
- 변경 전 CLS **0.1151** (Google "좋음" 기준 0.1 초과) → 변경 후 **0.0344**.
- 이번 변경으로 이동 폭이 줄었을 뿐 **원인(폰트 스왑)은 그대로**입니다.
- 근본 해결(`size-adjust` 폴백 폰트 지정 등)은 폰트 설정 변경이라 이번 범위 밖입니다.

## 이 문제들이 최종 판정에 미치는 영향

B-1 은 **기능 결함**, B-2 는 **접근성 기준 미달**입니다.
지시서 4절 "심각한 기존 문제가 발견되면 '원래 있었다'는 이유로 전체 안전성을 보증하지 않는다.
안전상 그대로 반영할 수 없는 기존 문제는 승인 필요 항목으로 분리하고, 검토 준비 상태를 제한한다"
에 따라, 이 두 건을 **검토 준비 상태를 제한하는 요소**로 명시합니다.
