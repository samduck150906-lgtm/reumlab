# 계약 이후 접근 권한 온보딩 절차

`/ai-search-optimization/` 은 **고객의 운영 중인 사이트를 직접 수정**하는 서비스라, 계약 뒤에 고객 자산에 대한 접근 권한을 받아야 한다. 이 문서는 그 권한을 **안전하게** 받는 절차를 정한다.

원칙 하나만 기억하면 된다: **비밀번호를 받지 않는다. 초대를 받는다.**

## 1. 계약 전 (상담 단계)

받는 것: 사이트 주소, 개선하고 싶은 점, 홈페이지 환경, 수정 권한 보유 여부, 관심 패키지.
전부 상담 폼의 선택지이거나 자유 서술이고, **사업·프로젝트 정보**다.

받지 않는 것 — 폼에 항목 자체를 두지 않았고, 검증 스크립트(`scripts/verify-ai-search-page.mjs`)가 이런 이름의 필드가 생기면 빌드를 실패시킨다:

- 계정 비밀번호 · 인증코드(OTP) · API 키 · 액세스 토큰
- 고객 명단 · 회원 DB · 결제 정보 · 건강정보

고객이 상담 내용에 이런 값을 직접 적어 보낸 경우: **즉시 해당 자격증명을 변경(회전)하도록 안내**하고, 접수 내역에서 그 값을 지운다. 채팅·이메일로 다시 보내달라고 요청하지 않는다.

또 하나: 이 페이지는 입력한 주소를 **자동으로 열어 보지 않는다.** 서버가 임의 URL 을 대신 읽어 주는 기능을 만들면 SSRF 공격면이 생기기 때문이다. 주소는 사람이 상담에서 확인한다.

## 2. 계약 이후 — 권한 요청 순서

### 2-1. 무엇을 바꿔야 하는지부터 확정
합의한 수정 대상 페이지·템플릿 목록을 먼저 확정한다. 필요한 권한은 그 목록에서 나온다. "일단 관리자 권한 주세요" 로 시작하지 않는다.

### 2-2. 환경별 요청 방식

| 환경 | 요청하는 것 | 요청하지 않는 것 |
|---|---|---|
| 코드 기반 (Next.js·React 등) | Git 저장소 **협업자 초대**(개인 계정 단위), 필요한 경우 배포 플랫폼의 팀 초대 | 저장소 소유자 계정 로그인, 배포 토큰 원문 |
| WordPress | 작업 계정 **신규 생성** 후 초대. 역할은 필요한 최소(편집자/관리자 중 합의한 쪽) | 기존 관리자 계정의 아이디·비밀번호 |
| 아임웹 · 카페24 · Wix | 플랫폼이 제공하는 **운영자/직원 초대** 기능 | 대표 계정 공유 |
| 검색 도구 | Google Search Console: **사용자 추가**(권한 '제한적' 또는 '전체' 중 합의). 네이버 서치어드바이저: 사이트 소유자 추가 | 구글·네이버 계정 자체 |
| 분석 | GA4 속성 **사용자 추가**(뷰어 또는 분석가) | 계정 비밀번호 |
| 서버·호스팅 (필요할 때만) | 별도 작업 계정 + 키 기반 접속. 실비·범위는 계약에 명시 | 루트 비밀번호 |

공통 규칙:
- **개인 계정 단위 초대**만 받는다. 공용 계정을 나눠 쓰지 않는다.
- 권한은 **작업에 필요한 최소 범위**로 시작하고, 부족하면 그때 올린다.
- 2단계 인증이 걸린 계정을 대신 로그인하는 방식은 쓰지 않는다.

### 2-3. 부득이하게 비밀번호를 받아야 한다면
플랫폼에 초대 기능이 아예 없는 경우가 있다. 그때도 이메일·카카오톡·문자로 받지 않는다.

1. 고객이 **일회성 비밀번호를 새로 만들어** 전달한다(기존 비밀번호 재사용 금지).
2. 전달은 만료·1회 열람이 되는 수단을 쓴다.
3. 작업이 끝나면 고객이 **즉시 변경**한다.
4. 받은 값은 어디에도 저장하지 않는다. 저장소·문서·이슈·스크린샷에 남기지 않는다.

## 3. 작업 중

- 운영에 바로 올리지 않는다. 테스트 환경에서 확인한 뒤 합의된 방식으로 반영한다(`SEO_PRESERVATION.md` 의 보존 원칙과 같다).
- 고객 사이트의 실데이터(회원·주문·문의 접수 내역)를 로컬로 내려받지 않는다. 필요한 경우 범위·기간·파기 시점을 계약에 적는다.
- 스크린샷·로그에 고객의 개인정보가 찍히면 공유 전에 지운다. 공개 저장소·정적 배포 폴더에 넣지 않는다.
- `.env` 값, 토큰, 접속 정보는 커밋하지 않는다.

## 4. 납품·종료 시 (권한 반납)

인수인계와 **같은 자리에서** 처리한다. 프로젝트가 끝났는데 접근 권한이 남아 있는 상태를 만들지 않는다.

- [ ] 변경 내역·수정 파일 목록·QA 결과·운영 가이드 전달
- [ ] Git 저장소 협업자에서 제외
- [ ] CMS·빌더 작업 계정 비활성화 또는 삭제
- [ ] Search Console · 서치어드바이저 · GA4 사용자에서 제외
- [ ] 서버 접속 키 폐기
- [ ] 2-3 경로로 받은 비밀번호가 있었다면 고객이 변경했는지 확인
- [ ] 보관 중인 고객 자료 중 계약상 보관 사유가 없는 것 파기

## 5. 아직 정하지 못한 것

- 고객 자료의 **보유 기간**은 실제 계약서 문구와 맞춰야 한다. 확인 전까지 이 문서·화면·개인정보처리방침에 기간을 지어 넣지 않았다.
- 해외 이전·수탁자(외부 도구 이용) 조건도 같은 이유로 비워 두었다. 사용하는 도구가 확정되면 개인정보처리방침에 반영한다.
