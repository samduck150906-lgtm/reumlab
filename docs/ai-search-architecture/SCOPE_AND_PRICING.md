# AI Search Architecture — 가격과 범위

**이 문서는 설명서이고, 값의 단일 출처는 `lib/ai-search-architecture.ts` 다.**
가격을 바꿀 때는 그 파일만 고친다. 화면·비교표·구조화 데이터(`Offer.priceSpecification.minPrice`)·FAQ 가 모두 거기서 파생되고, `npm run seo:verify:ai-search` 가 셋이 어긋나면 빌드를 실패시킨다.

## 1. 구축 패키지 — 모두 VAT 포함 시작가

| | START | GROWTH (권장) | ENTERPRISE |
|---|---|---|---|
| 시작가 | **250만 원부터** (2,500,000원) | **390만 원부터** (3,900,000원) | **690만 원부터** (6,900,000원) |
| 기술 진단 범위 | 공개 HTML 최대 100 URL | 최대 300 URL | 최대 1,000 URL |
| 실제 수정 페이지 | 최대 3개 | 최대 7개 | 최대 12개 |
| 공통 템플릿 개선 | 최대 1종 | 최대 2종 | 최대 3종 |
| 기간 | 약 2주 | 약 3~4주 | 약 4~6주 |
| 기준 | 자료·접근 권한 수령 후, 범위 확정 기준 | 〃 | 기술 구조와 범위 확정 후 안내 |

공통: 단일 도메인·한국어 사이트 1개.

### 진단 URL 과 실제 수정 페이지는 다른 개념이다
- **진단 URL** = 기술 상태를 확인하는 범위.
- **실제 수정 페이지** = 개별 콘텐츠·구조를 직접 개선하는 계약 대상.
- 공통 템플릿 수정이 여러 URL 에 반영될 수는 있지만, 모든 URL 의 개별 원고 작성·개별 최적화를 뜻하지 않는다.

이 구분은 화면(가격 카드 배지 + 비교표 + FAQ `진단 300 URL과 실제 수정 7페이지는 어떻게 다른가요?`)에 그대로 적혀 있다.

## 2. 명시적 제외

START 카드에 적힌 제외 항목(다른 패키지도 동일 기준): 신규 사이트 제작 · 도메인 이전 · 로그인 영역 · 앱 내부 · 신규 CMS·DB · 대량 원고 생산 · 지속 모니터링.

별도 견적이 필요한 범위: 다국어 · 여러 도메인 · 수천 URL 이상의 별도 데이터 정비 · 쇼핑몰 상품 DB · 복잡한 CSR 구조 전환 · 플랫폼 이전 · 새로운 CMS·서버 기능 · 외부 시스템 연동.

계약 범위 밖의 기능·새 페이지·외부 도구 이용료·유료 광고·호스팅 실비는 자동 포함되지 않는다.

## 3. 선택형 AI Search Care (구축 계약과 별도)

| | CARE | CARE PLUS |
|---|---|---|
| 요금 | 월 39만 원 (390,000원, VAT 포함) | 월 69만 원 (690,000원, VAT 포함) |
| 기술 상태 확인 | 주요 페이지 최대 10개 / 월 1회 | 최대 20개 / 월 1회 |
| 응답 관찰 | 고정 질문 10개 × 서비스 2곳 × 1회 (최대 20개) | 20개 × 3곳 × 1회 (최대 60개) |
| 리포트 | 월간 1회 | 월간 리포트 + 우선순위 제안 각 1회 |
| 경미한 수정 | 기존 페이지 1개 | 기존 페이지 최대 2개 |

**이 페이지에서는 결제·구독이 일어나지 않는다.** 상담 폼의 `지속 관리 관심` 기본값은 `없음` 이고, 방문자가 원치 않는 구독이 선택된 상태로 시작하지 않는다(게이트가 기본값을 검사한다).

월 1회 관찰은 고정 표본 모니터링이며, 전체 AI 노출률을 통계적으로 추정하는 방식이 아니다. 기간·해지·환불·추가 작업 조건은 실제 계약으로 정한다.

## 4. 보장하지 않는 것 (화면에도 그대로 적혀 있다)

- 검색 순위, 색인 반영 시점, AI 추천·인용, 매출 성과.
- 모든 플랫폼에서 동일하게 전면 수정 가능하다는 보장.
- 기존 검색 순위의 유지.

`scripts/verify-ai-search-page.mjs` 의 금지 표현 검사가 "순위 보장 / 노출·추천 보장 / 상위노출 보장 / 무제한 / 평생 / 100%" 를 잡는다. 같은 단어라도 `보장하지 않습니다` `적합하지 않습니다` 처럼 부정·거절 문맥이면 통과시킨다(문장 단위로 판정).

## 5. 값을 고치는 방법

1. `lib/ai-search-architecture.ts` 의 `PACKAGES` / `CARE_PLANS` 수정.
2. `scripts/verify-ai-search-page.mjs` 의 `BASELINE.packages` / `BASELINE.care` 를 같은 값으로 수정.
   — 게이트는 "승인된 값" 을 들고 있어야 의미가 있다. 통과시키려고 현재 출력에 맞추는 용도가 아니다.
3. 전역 가격 검사(`scripts/verify-pricing.mjs`)의 `RETIRED_PRICE_EXCEPTIONS` 확인.
   현재 `690만` 은 구 홈 요금표 잔재라 전역 금지어인데 이 페이지의 현행 시작가와 문자열이 겹쳐,
   `/ai-search-optimization/` 안에서만 허용하도록 **경로 한정 예외**를 뒀다. 금액이 바뀌면 이 예외도 같이 정리한다.
4. `npm run build && npm test` 로 화면·스키마·게이트가 함께 맞는지 확인.
