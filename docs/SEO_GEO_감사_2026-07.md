## A. 종합 진단

| 축 | 수정 전 | 수정 후 | 근거 |
| --- | --- | --- | --- |
| 테크니컬 SEO | **B** | **A−** | 색인 게이트·canonical·사이트맵·리디렉션 설계는 이미 매우 성숙(중복 title 0, alt 누락 0, width/height 누락 0, 사이트맵 3xx/4xx 0). 다만 404 메타 상속, canonical→301 체인, 법적 페이지 사이트맵 누락이 있었음 → 전부 수정. |
| GEO | **C** | **B+** | 사이트의 핵심 신뢰 자산(포트폴리오 15건)이 HTML에 한 글자도 없었고, 사이트 전역 가격이 홈과 2배 어긋나 AI가 인용할 "일관된 사실"이 없었음. llms.txt 부재, 동작하지 않는 SearchAction 선언. → 전부 수정. |
| 전환 구조 | **C+** | **B** | 홈(`script.js`)의 폼 추적은 성공 응답 기준·start/submit 분리·UTM 유지까지 모범적. 그러나 검색 유입이 실제로 도착하는 나머지 1,400여 페이지에는 전화·이메일 클릭 계측이 사실상 없었음 → 전역 위임으로 해결. |

### 가장 심각했던 문제 5개

1. **사이트 전역 가격이 라이브 홈과 정확히 2배 어긋나 있었음.** 홈은 웹 98만/앱 580만, 나머지 전 페이지(965개소)는 49만/290만. 검색 스니펫에 "290만원부터"가 노출되고 클릭하면 580만원이 보이는 구조 → 신뢰 붕괴·이탈. **대표 확인 결과 홈(98만/580만)이 정가**로 확정, 전량 정정.
2. **JSON-LD Offer(98만/580만)와 같은 페이지 본문(49만/290만)이 불일치.** 구조화 데이터와 화면 내용 불일치는 Google 구조화 데이터 정책 위반이며 리치 결과 박탈 사유.
3. **포트폴리오 15건이 클라이언트 렌더 전용.** `<div id="pfGrid">`가 빈 채로 배포되고 `script.js`가 채움 → 네이버 Yeti·생성형 검색 크롤러(GPTBot·ClaudeBot·PerplexityBot 등 대부분 JS 미실행)는 름랩의 실적을 **전혀 볼 수 없었음**. 신뢰·인용 근거가 통째로 비어 있던 상태.
4. **404 페이지가 홈 메타데이터를 상속.** `out/404.html`·`out/404/index.html`이 홈과 동일한 title·description에 `canonical=홈`, `robots=index,follow`를 함께 내보내 soft-404·중복 신호 발생.
5. **검색 유입의 대부분이 도착하는 페이지에 상담 전환 계측 없음.** 전화·이메일 링크가 1,413개 페이지에 있으나 `click_phone`/`click_email` 이벤트는 홈에서만 발화.

### 가장 큰 성장 기회 5개

1. **가격 선공개가 실제 시장 대비 강한 차별점.** 웹 검색 기준 동급 앱 외주 시세는 1,500만~4,000만 원대로 인용됨. 름랩 580만~1,980만은 명확한 가격 우위이며, "가격을 먼저 공개"는 경쟁사 대부분이 하지 않는 행동 → 비교형·비용형 키워드에서 인용 확률이 높음.
2. **소스코드·계정 권한 이관을 계약 조항 수준으로 문서화.** 시장에서 이 항목이 반복적으로 "확인해야 할 리스크"로 언급됨 → 정면으로 답하는 페이지는 인용 자석이 됨.
3. **포트폴리오 `detail`(구조·사용자 흐름·기술·산출물)을 크롤 가능한 텍스트로 승격.** 데이터는 이미 있고 모달에만 갇혀 있음(§D 미완료 항목).
4. **업종×비용 축(`/cost/*`)의 3단계 가격대 구조**는 AI가 표로 추출하기 좋은 형태. 정가 정합성이 잡혔으므로 이제 인용 가치가 생김.
5. **llms.txt로 사실 단일 출처 확보.** 1,400개 페이지 중 어디로 진입해도 같은 금액·기간·정책을 인용하도록 고정.

### 검색엔진·AI가 현재 름랩을 어떻게 이해할 가능성이 높은가

- **수정 전**: "동탄·수원 기반 앱·웹 외주 개발사. 가격은 페이지마다 다르게 나옴(49만/98만/290만/580만이 혼재) → 가격 인용 회피." 포트폴리오는 존재를 알 수 없어 "실적 불명"으로 처리될 가능성.
- **수정 후**: "름랩(REUMLAB)은 앱·웹·관리자 페이지·MVP를 기획부터 배포까지 구축하는 앱·웹 개발 스튜디오. VAT 포함 정액(웹 98만~, 앱 580만~), 소스코드 전량 이관, 동탄·화성·수원 거점 전국 진행." — 홈 히어로 정의문 + llms.txt + JSON-LD가 같은 문장을 반복하므로 엔티티가 하나로 수렴.

### 목표 키워드에서 노출이 어려웠던 핵심 이유

색인·크롤 구조 문제가 아니라(그쪽은 이미 우수) **콘텐츠 신뢰 신호의 공백**이 컸음: ① 가격이 페이지마다 달라 "믿을 수 있는 견적 출처"로 취급되기 어려웠고, ② 실적(포트폴리오)이 HTML에 없어 E-E-A-T 근거가 비었으며, ③ 홈 외 페이지의 전환 계측이 없어 "어떤 키워드가 상담을 만드는지" 학습·개선 루프 자체가 돌지 않았음.

## H. 대표가 제공해야 할 자료

코드만으로 해결할 수 없는 항목:

1. **업종별 표준형·고급형 가격대 확인** — `/cost/*` 100여 업종의 3단계 구간을 ×2로 기계 변환했음. 실제 견적 감각과 맞는지 확인 필요. (가장 우선)
2. **`/soho/` 특가 유효기간** — "이번 달 한정 49만원"의 종료 시점. 종료 시 정가 98만원으로 되돌릴지 결정.
3. **실제 고객 후기** — 현재 사이트·스키마 모두 후기·평점이 없음(정직한 상태). 확보 시 게재 동의 범위 포함.
4. **공개 가능한 프로젝트 화면** — 포트폴리오 15건은 텍스트 설명만 있고 실제 화면은 CSS 목업. 익명화된 실제 스크린샷이 있으면 신뢰도가 크게 오름.
5. **유지보수 범위·요금 정책** — "월 관리비 없음"은 명시돼 있으나, 유상 유지보수의 단가·범위가 문서화돼 있지 않음.
6. **무상 오류 수정 기간** — FAQ에 "기본 오류 확인 기간"으로만 표기됨. 구체적 일수 확정 필요(경쟁사는 "1개월 무상"을 명시).
7. **계약 후 절차** — 상담 → 견적 → 계약 → 착수까지의 단계와 소요일. 현재 "상담 후 안내"로만 되어 있어 AI가 인용할 절차가 없음.
8. **영업시간 확정** — 스키마에 `Mo-Fr 10:00-18:00`으로 선언됨. 실제와 다르면 수정 필요.
9. **네이버 플레이스·GBP 현재 등록 정보** — 사이트와 상호·전화·주소가 일치하는지 대조 필요.
