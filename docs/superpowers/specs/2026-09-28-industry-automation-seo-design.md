# 산업별 AI·업무자동화 서비스 확장 설계

## 목표

름랩의 기존 `/ai-automation/` 허브를 유지하면서, 실제 프로그램과 반복 업무를 기준으로 탐색 가능한 산업별 자동화 서비스 구조를 추가한다. 검색어 연구 자산은 7,000개 이상 축적하되, 검색어 치환형 URL은 만들지 않는다.

## 출판 원칙

- 70개 분야를 데이터 모델과 검색어 연구 범위에 포함한다.
- 공개 상세 URL은 Priority S 중 고유한 도구·업무·제약·워크플로·FAQ가 갖춰진 항목만 생성한다.
- Priority A/B 항목은 허브에서 상담 가능 분야로 보여 주되 링크와 URL을 만들지 않는다.
- 기존 URL, canonical, 네이버 보호 기준선, 문의 폼 이름과 필드를 삭제하거나 변경하지 않는다.
- 가격·성과·파트너십·공식 API 제공 여부를 추정하지 않는다.
- 공식 API, SDK, 플러그인, 파일 교환, 브라우저/데스크톱 자동화, 사람 검수 순서로 구현 가능성을 설명한다.

## 정보 구조

- `/ai-automation/`: 기존 정적 목적 랜딩. 검색·카테고리 필터와 70개 분야 디렉터리를 추가한다.
- `/ai-automation/[slug]/`: Priority S 상세 서비스. 정적 생성, self-canonical, Service/WebPage/Breadcrumb/FAQ 구조화 데이터, 문의 폼을 제공한다.
- `lib/automation-domains.ts`: 분야·도구·업무·워크플로·제약·FAQ·연결 서비스의 단일 출처.
- `content/seo/automation-keywords.{json,csv}`: 검색어 연구 자산.
- `content/seo/automation-questions.json`: 자연어 AEO 질문 연구 자산.

## 품질 게이트

상세 페이지는 다음을 모두 만족해야 공개된다.

1. 도구 5개 이상, 실제 업무 5개 이상, 워크플로 5개 이상
2. 기술적 제약과 사람 검수 지점 명시
3. FAQ 6개 이상
4. 고유 title, description, H1, canonical
5. 기존 `decideFromContent` 색인 점수 80점 이상
6. 페이지 간 본문 Jaccard 유사도 0.70 미만
7. 사이트맵에는 위 조건을 통과한 URL만 포함

## 검색어 연구

각 분야의 제품명·업무·개발형 의도·구매형 의도를 조합하고 중복을 제거한다. 각 레코드는 targetPage와 clusterId를 가져 공개 페이지 수와 분리된다. 자연어 질문은 분야별 30개 이상을 생성한다.

## UX·전환

기존 름랩 디자인 토큰과 헤더·푸터를 재사용한다. 허브 필터는 JS가 꺼져도 전체 목록이 보이는 점진적 향상 방식이며, 상세 페이지는 서버 HTML에 핵심 답변과 전체 내용을 제공한다. 문의는 기존 Netlify `main-apply` 흐름을 재사용하고 자유 설명 한 칸을 유지한다.

## 비범위

- 70개 분야를 모두 별도 색인 URL로 발행
- 지역명·업체·비용 단어만 바꾼 변형 페이지
- 외부 플랫폼 계정에서의 수동 색인 요청
- 근거 없는 가격, 실제 사례, 성과, 인증, 공식 파트너 표현
